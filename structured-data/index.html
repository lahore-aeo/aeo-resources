Structured data for search: safe implementation

Structured data is machine-readable description of visible page content. Use it to express facts accurately, not to promise a search feature.

Match markup to visible content

Choose a schema type that fits the page and describe information a visitor can verify on that page. Keep names, dates, offers, authors, and other properties consistent with visible content. If the page changes, update the markup too.

For a real editorial article, Article markup may describe its headline, author, publication date, and image. Organization markup may describe a real organization. Add only properties you can support and maintain.

Draft JSON-LD with the JSON-LD Schema Markup Generator, then validate it and compare the markup with the visible page in RankWox Tools.

Know what schema cannot do

Structured data does not force a page to rank, appear as a rich result, or be cited in AI-generated answers. Google explicitly says correct structured data does not guarantee a rich result. Hidden, misleading, irrelevant, or fabricated markup can make a page ineligible for search features and may create policy problems.

A useful rule: first make the page accurate and helpful for people; add markup only if it faithfully describes that page.

Validate and maintain it

  1. Read the search platform's documentation for the chosen schema feature.
  2. Validate syntax with the appropriate testing tools.
  3. Compare the markup against visible page content.
  4. Check Search Console reports after deployment.
  5. Recheck when the page template or content changes.

For access and indexing checks, see crawlability and indexing. For Google's current policies, read its general structured data guidelines.
