Crawlability and indexing: the practical checks

A page cannot earn organic visibility if search systems cannot access it or decide it is ineligible. Start with simple URL-level checks before adding advanced optimization.

Separate crawling from indexing

Crawling is a system fetching a URL. Indexing is the process of analyzing and potentially storing the page for search. A successful fetch does not guarantee indexing, and indexing does not guarantee that a page will be shown for a query.

Check the fundamentals

  1. Open the exact URL and confirm it returns the intended page, not an error or redirect loop.
  2. Review robots.txt and page-level robots directives for accidental blocks.
  3. Use a self-referencing canonical where appropriate and avoid conflicting canonicals.
  4. Make sure important content is present in renderable HTML and not hidden behind required user actions.
  5. Link the URL from a relevant page and include it in a current sitemap when appropriate.
  6. Use Search Console inspection reports to see Google's reported crawl and index status.

Diagnose common causes

Thin or duplicate pages, soft 404s, noindex directives, canonical conflicts, server errors, and orphaned URLs can all affect eligibility or discovery. Fix the cause instead of repeatedly resubmitting a URL. For a small site, keep navigation shallow and use meaningful links so both people and crawlers can reach important pages.

For GitHub Pages projects, ensure each directory has an index.html, use paths that match the published project base, and check for 404s on direct page loads.

Use platform guidance as the source of truth

Google's AI search guidance says pages must meet the usual technical requirements and be eligible to appear in Search with a snippet. Google does not promise that every eligible page will be crawled, indexed, or served.
